### Where I differ from your sketch

1. **Key: an assigned slug, not a digest.** A digest of "stable" fields is only as stable as its inputs. Fix a typo in a name and the key changes, which breaks every reference to it, the exact failure it was meant to prevent. A slug is assigned once and never derived. Renaming means editing `common_name`, not the slug.
   - Dependencies become readable (`requires=collective;gekolib`), so you do not need a second concatenated key.
   - Duplicate prevention is a check on three columns: `slug`, `modlink`, `jar_file`. Calc's duplicate highlighting does it by hand, and a small script can do it later.
   - Privacy: by reading the patterns (not by running them), slugs match none of the 17. One catch: a **four-part version** such as `1.21.1.4` matches `ipv4-address`. Three-part versions and normal jar names do not. If that trips the hook, the fix lives in `scripts/`, which STATE.md says to leave alone until CT Claude decides. So we would raise it then.
2. **No stored "Group + Name" key.** Calc's two-key sort (`group`, then `common_name`) gives that view with nothing stored. A stored concatenation goes stale the moment a group changes.
3. **Drop `Order`.** The sort replaces it.
4. **Dependencies are stored once, forward only.** "Dependency For" is derived: filter `requires` for "contains `jei`". A small check that every slug in `requires` exists in the `slug` column catches the drift shown above. I would build it only after the table has real rows.
5. **`side` as one field, not two booleans.** Two booleans allow "neither" (and the old file's stray apostrophes). Three values cannot be invalid. `client` means "never ships in the server pack", which is the Sodium rule. Add a fourth value only when a real mod needs one. Your "deactivate with `.disabled`" question can later be answered from `side`: server-only elements are the candidates, and single-player needs them. It stays parked.
6. **`source` separate from `modlink`.** A column that is sometimes a URL and sometimes the word "Internal" cannot be validated or turned into links. `source=internal` with a blank `modlink` says the same thing.
7. **`size_kb` as a plain number**, so Calc can sum it. Convert MB to KB and record the rule in the README. Disk size is a sound budget proxy for your "size, not count" point, but it is not memory use. A small worldgen mod can cost more than a large content mod, and Spark is the real measurement. Per-mod measurements go in the `.md`.
8. **Lists use `;`, not commas**, so no field needs quoting. UTF-8, LF line endings, no formulas, no leading apostrophes.

### Things to know about the memory scale

- A single number cannot say whether it describes the client or the server. The README asks you to record the side in the element's notes file.
- Memory is not the same as processing cost. A mod can use little memory and still eat tick time. I did not add a second field, since you asked about memory, but the decision record lists it as open.
